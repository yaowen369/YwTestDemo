# CHAINWAY 成为 MC62 设备信息与 App 适配基线

记录日期：2026-11-09（亚洲/上海）\
用途：车站巡检工单 App 的后续交互、UI 设计与实现依据。当前仅记录设备信息及适配要求，未开展 UI 设计或修改业务代码。

## 1. 用户确认的设备范围

- 主要使用设备：CHAINWAY 成为 MC62，4 英寸屏幕，带实体键盘。
- 同时兼容没有实体键盘的普通 Android 手机。
- 所有业务操作均须能通过触屏独立完成；MC62 实体键盘提供部分操作的等效快捷方式，不成为完成工单的必要条件。
- 两类设备使用同一套工单流程、材料要求和状态规则。输入方式不能改变“开始处理即视为已到场”“成功提交即已完成、默认验收通过”的业务含义。
- 提醒规则一致：App 前台且屏幕可交互时提醒新单，后台、锁屏时不通知。

本文将用户要求、ADB 只读实测、官网型号规格和后续适配建议分开记录。静态硬件能力不等于 App 操作已经验证通过。

## 4. 实体键盘：已发现的能力与未验证项

主键盘输入设备为 `mtk-kpd`，本次节点是 `/dev/input/event0`。只读取了按键能力列表和系统键表，没有监听用户实际键入。

| 按键类别 | 驱动声明 | 系统通用键表映射名称 |
| --- | --- | --- |
| 数字 | 0～9 | 0～9 |
| 方向 | 上、下、左、右 | DPAD_UP、DPAD_DOWN、DPAD_LEFT、DPAD_RIGHT |
| 确认、删除 | ENTER、BACKSPACE | ENTER、DEL |
| 取消与字符 | ESC、DOT、CAPSLOCK、NUMERIC_POUND | ESCAPE、PERIOD、CAPS_LOCK、POUND |
| 其他功能 | F15～F18、FN | F15～F18、FUNCTION |
| 独立电源按键设备 | POWER、F14 | 电源及厂商功能键，实际键帽对应待验证 |
| 独立导航按键设备 | BACK、HOMEPAGE、APPSELECT | BACK、HOME、APP_SWITCH |

可复核的 Linux 扫描码与键表名称：1→ESCAPE；2～10→1～9，11→0；14→DEL；28→ENTER；52→PERIOD；58→CAPS_LOCK；103/105/106/108→上/左/右/下；185～188→F15～F18；464→FUNCTION；523→POUND。导航键 158→BACK、172→HOME、580→APP_SWITCH，184→F14。

以上数字是 Linux 扫描码，不是 Android `KeyEvent` 常量值。键表来自 `/system/usr/keylayout/Generic.kl`，属于静态映射依据；尚未证明每个实体键都会把相同事件交给当前 App。

本机配置字符串包含 `nokeys`，但驱动实际声明了实体键盘。因此后续不能仅通过“是否为 QWERTY 键盘”或一个系统配置字段来决定是否处理按键。驱动节点编号也不能写死在 App 中。

尚未验证：实体键帽与事件的逐一对应、Fn 组合、左右扫描键、多功能键的行为，以及输入法或厂商服务是否拦截事件。扫码功能不是本期完成工单的前提。

## 6. 后续交互与适配要求

### 6.1 所有功能均可触屏完成

普通 Android 手机和 MC62 均可通过触屏完成：查看列表与详情、开始处理、选择结果类型、填写说明或配件类型、拍照或选图、检查材料、提交完成、查看成功或失败结果以及返回。

不能出现仅能按实体键触发的必经动作，不能只显示“按某键继续”而没有触屏入口。MC62 也应在不按实体键的情况下完成全流程。普通手机不要求额外连接键盘或具备扫描头、NFC 等工业终端专用能力。

### 6.2 实体键盘作为快捷补充

下列为后续交互设计建议，具体按键绑定须经过实按验证后确定：

| 操作 | 触屏基础能力 | MC62 键盘快捷方向 |
| --- | --- | --- |
| 浏览列表、选择控件 | 点击、滑动 | 方向键移动可见焦点，必要时自动滚动使其可见 |
| 打开工单、激活按钮 | 点击对应入口 | 确认键激活当前焦点，不全局固定为“处理完成” |
| 输入说明、配件类型 | 屏幕输入法，包括中文输入 | 可使用数字键等编辑；遵循输入框和输入法行为 |
| 返回、取消 | 页面返回入口或系统返回操作 | 已验证的返回/取消键；保持与触屏相同的材料保留规则 |
| 开始处理、提交完成 | 页面提供明确操作 | 聚焦到对应操作后等效激活，仍校验必填材料并等待后台响应 |

键盘与触屏可随时切换，同一张工单的输入和焦点应保持合理。输入框内不抢占数字、方向、退格等正常编辑行为；多行说明中的回车不能误触完成。功能键、扫描键与 Fn 组合不在未经验证时绑定业务动作。长按、抖动或连续按键不能形成重复提交。

这不要求一期所有输入和拍照动作完全脱离触屏，也不要求建设快捷键自定义功能。

### 6.3 小屏、软键盘和普通手机

- 后续设计先验证 MC62 的 320dp 窄屏，普通手机按实际可用宽高适配，不硬编码 480×800px 或 320×509dp。
- 优先采用能滚动的内容组织，长位置、长说明、错误提示和多张照片均可查看，关键操作不因屏幕短而无法到达。具体布局留在 UI 阶段确定。
- 输入说明、配件类型时允许调起中文软键盘，包括 MC62；有实体数字键不能替代中文输入能力。
- 输入法展开后，正在编辑的字段和继续操作入口应能通过滚动或收起输入法到达；不得遮挡到无法完成，也不得清空已填材料。
- 系统栏、手势导航区、刘海区域、输入法高度按实际窗口处理。MC62 当前没有底部导航栏占位，不代表普通手机也没有。
- 后续 UI 建议触控区域至少 48dp；常规正文可从约 16sp 起评估，并验证系统字体放大后的可读性。具体字号、间距和样式由后续 UI 设计确定，不通过无限缩小文字解决拥挤。
- 按实际屏幕与输入能力适配，不仅按设备型号判断；普通手机可能存在不同导航方式和字体设置。

### 6.4 性能与照片

按本机约 3GB 级内存设计图片处理。单张 4208×3120 的 ARGB 全尺寸位图约占 50MiB，不宜在列表中同时解码多张原图。后续采用适配展示尺寸的缩略图、控制缓存与上传占用，保留照片失败后的可恢复材料。

选择摄像头时核实面向与拍照能力，不能把“枚举到的第三个设备”自动认定为业务所需主摄或扫码头，也不能硬编码本次枚举顺序。

本机已安装 App：包名 `ywdemo.example.yaoxiaowen`，版本 1.4（versionCode 5），安装信息显示 minSdk 24、targetSdk 33。当前工程 compileSdk 33。这些是现状，不表示已完成 Android 7.0 及以上所有机型兼容验证；后续应记录选用普通手机的 Android 版本与实际测试结果。

## 7. 后续设备验收范围

以下均为**待执行**，设备资料采集完成不代表 App 适配通过：

1. MC62 320dp 窄屏全流程，包括长文本、多工单、多张照片和三种处理结果。
2. MC62 仅触屏操作，以及触屏与方向/确认/返回键混合操作；焦点始终可见。
3. 至少一台无实体键盘普通 Android 手机，仅靠触屏完成同样流程；记录实际型号、系统、分辨率、逻辑密度和导航方式。
4. 两类设备的中文软键盘输入、展开/收起、字段切换和材料保留；普通手机的手势或三键导航区域不遮挡操作。
5. 字体放大后的长文本、按钮、表单和错误提示可读、可操作。
6. 键盘长按、快速连按、输入框回车，以及新单到达期间的焦点和提交行为，不导致误提交或重复完成。
7. 拍照、选图、上传失败与重试、低内存下返回页面和草稿恢复。
8. 两类设备仅前台提醒；后台或锁屏不通知，回前台正确同步新单。

adb -s '<设备序列号>' shell getprop ro.product.model
adb -s '<设备序列号>' shell getprop ro.build.version.release
adb -s '<设备序列号>' shell wm size

adb -s '<设备序列号>' shell getevent -lp
