## 1. 一期目标

只完成两个可操作的流程：

1. 智慧车站 `/fullspace/station`：查看异常检查，在原证据弹窗点击“下发工单”，看到下发成功及已下发状态。
2. Android App：支持从延时收到新工单通知开始，点击通知查看工单，开始处理，填写现场结果，拍照或选图，看到上传成功、提交成功及完成记录。

**两端独立运行，业务效果均由本机数据模拟。** 大屏下发不会实际向 App 发送工单，App 提交不会回写大屏，也不调用真实上传、工单或验收接口。

新增来单使用手机本地定时触发和 Android 系统通知，真实显示通知栏消息并按系统设置发出声音和振动；无需服务端或第三方推送平台。

**App 的呈现完全按正式产品处理。** 页面、按钮、提示、照片标记、工单编号和完成记录不出现“模拟”“演示”“示例”“占位”等字样；上传、提交、验收均使用正常业务文案。模拟边界只写在开发和验收文档中，不铺到 App 业务界面。

## 4. App 需求

- App 正式名称为“智慧车站”，页面及后续系统通知使用该名称。
- 固定使用李明身份，直接进入“我的工单”，不增加登录、人员选择或值班管理。

### 4.3 三类结果与材料

| 结果 | 必填材料 | 完成后的表达 |
| --- | --- | --- |
| 已处理 | 处理说明，至少一张处理后照片 | 工单已完成，保留处理说明和照片 |
| 核查无异常 | 核查说明，至少一张现场照片 | 工单已完成，原异常证据仍保留 |
| 需配件支持 | 配件类型文本 | 工单已完成，仍需配件支持；不写成设备已修复 |

配件类不额外要求照片或说明，也不受其他分支照片状态影响。无依据的照片数量上限、固定配件字典、采购和后续维修流程不加入一期。

### 4.4 按正式界面呈现上传和提交

1. 真实拍照或选图后，将可读取照片保存在本机；显示缩略图与来源。
2. 本机推进照片状态，界面依次显示“待上传”“正在上传”“上传成功”，不发送网络上传请求。
3. 当前分支选入的照片均达到上传成功后，才允许完成；缺说明、缺照片或缺配件类型时，在对应字段提示并保留输入。
4. 点击“提交并完成”后显示“正在提交…”，防止重复点击；本机保存完成结果成功后显示“提交成功”，进入完成记录。
5. 完成记录显示“系统默认验收通过”；不增加王飞人工验收或管理台代录流程。
6. 上传或提交的正常界面不得附加“这是模拟”“没有真实上传”等说明。内部模拟状态和技术标识不直接展示给工作人员。
7. 本机照片读取、权限或保存失败必须如实反馈，不能为演示成功而丢失照片、保存空白材料或在保存失败时显示完成。拍照取消保留原输入；相机不可用时仍可从相册选图。

上传状态是本机演示状态，不代表文件已到服务器。断网不阻止本期演示，不以网络连通性作为成功条件，也不建设真实上传重试队列或服务端结果查询。

### 4.5 本机保存与重新演示

- 按工单和结果分支分别保留说明、配件类型、照片及所选结果；返回、切换工单、调用相机或相册不丢材料。
- 退出重开后恢复列表状态、已完成记录和未提交材料。照片要能重新读取，不能只恢复缩略图或文件名。
- 延时来单的计划、本次选定场景及数量、目标时间和是否已加入工单也保存到本机，不因返回桌面、划掉最近任务或重新打开 App 而丢失、提前执行或重复执行；不能在计划触发时重新读取默认三项而替换已确认的自定义选择。
- 对本机保存失败明确提示，不承诺已经保留。
- “清除本地数据”统一放在 4.7 的隐藏调试模块，确认后清除本 App 的工单演示状态、未提交材料及本机处理记录，并立即恢复默认三项工单，12 项场景库继续可选；普通业务菜单不再提供该入口。不得删除系统相册中的用户原图。
- 无草稿时不固定显示草稿说明；没有记录时不虚构处理或验收人员。

### 4.6 UI 与设备要求

### 4.7 隐藏调试模块

参考车站大屏（`/fullspace/station`）“D4 · 巡检调试面板”的作用对象、快捷操作、运行参数和状态信息分组。已核对其当前组件 `InspectionDebugPanel.vue` 及入口：大屏为离线图标快速三击；App 按本次要求采用四连点，入口和按钮作如下细化建议。

#### 入口与页面

- 在“我的工单”列表顶部标题上，**2 秒内连续点击 4 次**，打开“工单调试”。不足 4 次不触发；超过时限、点击其他位置、滑动、长按或离开页面后重新计数，成功进入后也清空计数，不累积为下次进入的次数。
- 正常单击、双击、三击不跳转，也不显示剩余点击次数。普通列表、详情、填写和完成页不新增调试按钮、底部导航或常驻提示。
- 采用独立、可滚动页面，沿用 App 深蓝底与卡片样式，按“状态信息—工单操作—操作设置—重新开始”分组；“重新开始”区包含场景选择和等待时间。12 项按 A01／A02 分组纵向排列，显示名称、来源及选中状态，适配 MC62 320dp 宽度。
- 顶部返回按钮和 Android 系统返回均可退出；正常退出回到原列表分类和滚动位置。“清除本地数据”后返回“待处理”列表顶部；“重新开始”成功后自动返回手机桌面。
- 调试页、确认框和操作反馈同样不出现“模拟”“演示”“示例”“占位”等字样。页面名用“工单调试”，正常反馈用“重置成功”“已清除未提交材料”“设置已恢复”等。

#### 操作范围

| 分组／按钮 | 行为与影响范围 |
| --- | --- |
| 状态信息 | 展示待处理、处理中、已完成数量；选定工单后展示编号、问题、当前状态、有无草稿、当前结果分支及各分支照片数量与上传状态；有来单计划时显示“等待到达”、该计划的场景清单、预计到达时间和工单数量，只读查看 |
| 作用工单 | 从当前已到达的工单中选择一张，选项显示问题和编号；初次进入不默认选中。未选定时禁用单张工单操作，不默认操作第一张；该选择只用于重置或清除材料，与新一轮的场景选择独立 |
| 重置所选工单 | 将所选工单恢复为待处理，清除其开始时间、各结果分支材料、上传状态、完成与验收记录；保留原始问题、位置、编号和检查证据。其他工单不变 |
| 清除未提交材料 | 仅对所选的、有草稿的处理中工单可用；清除其全部结果分支材料与结果选择，保留处理中状态、开始时间和原始检查证据，下次从选择现场结果继续。已完成工单不可使用此操作 |
| 清除本地数据 | 取消未到达的来单计划、移除旧工单通知，立即恢复默认三项工单至首次启动状态；清除全部草稿、处理照片、开始／完成／验收记录及列表位置，操作设置和场景选择恢复默认；保留 12 项场景库及原始检查证据 |
| 操作速度：正常／快速 | 默认正常；快速缩短照片上传与提交的本机等待时间，仍须可见“正在上传”“上传成功”“正在提交”“提交成功”。只影响设置后新开始的操作，不跳过必填校验、本机文件保存或实际权限处理 |
| 恢复默认设置 | 将操作速度恢复正常，不改动工单状态、草稿、照片或完成记录 |
| 场景选择：默认三项／单项／多项 | 默认三项固定为垃圾桶、消火栓、闸机；单项从 12 项中单选 1 项，多项从 12 项中勾选 2～12 项；详细规则见下文 |

| 恢复默认三项 | 将待确认的场景配置恢复为垃圾桶、消火栓、闸机，不修改当前工单或已安排的计划 |
| 来单等待时间 | 建议默认 1 分钟，提供“1 分钟”“2 分钟”和自定义正整数分钟；空值、0、负数和非整数不可确认。显示本次所选场景名称与将到达的工单数量 |
| 重新开始 | 经确认后清除全部现有工单与处理材料，替换旧来单计划、移除旧通知，按本次所选场景安排延时来单并返回桌面；每个所选场景一张工单，不自动追加未选场景；详细规则见 4.8 |

#### 场景选择规则

1. 未主动选择自定义场景时使用“默认三项”，固定为垃圾桶、消火栓、闸机，明确显示“已选择 3 项，将生成 3 张工单”。12 项表示可选范围，不表示每次全部生成。
2. “单项”采用单选列表，一次恰好选择 1 项；未选择时提示“请选择 1 项异常场景”，禁止重新开始。选择某项后不叠加默认三项。
3. “多项”采用多选列表，初始勾选默认三项，用户可自由修改或全选；合法数量为 2～12 项。仅剩 1 项时提示“请选择至少 2 项，或切换为单项”；0 项同样不能开始。校验失败不清除现有工单、不取消原计划、不退出 App。
4. 页面始终显示本次所选名称和数量；同一场景只计一次，A01 与 A02 的电扶梯分别计数。确认框展示相同的场景清单，工单数量与所选项数一致；默认 3 张、单项 1 张、多项为实际勾选数量。
5. 自定义选择只应用于本次“重新开始”；成功安排后，下次发起新一轮的默认配置回到“默认三项”。取消确认或准备失败时保留当前选择供修改或重试。已安排计划独立保存所选场景，不能被配置回默认、重新打开 App 或点击“恢复默认三项”改变。
6. 改变选择本身不立即新增、删除或重置工单。只有确认重新开始，才按本次选择替换来单计划；已到达工单和草稿继续按原状态保存，直到用户明确执行相应重置操作。
7. App 页面用“场景选择”“默认三项”“单项”“多项”“已选择 N 项”等文案，不显示“单项模拟”“模拟全部”等字样。

#### 重置与保存规则

1. 重置所选工单、清除未提交材料、清除本地数据、重新开始均先确认，明确指出作用工单或全部工单，以及将清除的材料；提供“取消”和对应执行按钮。取消或关闭确认框不修改数据。
2. 重置及清除只影响本 App 对应的本机数据和照片副本，不删除系统相册原图，不影响其他工单仍引用的文件，也不操作大屏数据。
3. 重置时终止对应工单尚未完成的本机上传、提交状态推进；后续旧操作结果不得重新写回已清除的数据或弹出旧的成功提示。原有材料编辑状态同时失效，不能再次保存旧草稿覆盖重置结果。
4. 操作完成后立即刷新工单数量、状态和材料信息，并保存到本机；退出重开后保持重置结果。保存失败明确提示，不显示重置成功，也不留下已删除照片却仍有有效完成记录的状态。
5. 进入、退出调试页本身不改变任何业务数据。速度设置关闭调试页后继续生效，重新启动 App 后恢复正常；工单和材料仍按 4.5 持久保存。
6. 本期调试范围为本机状态查看、数据重置、12 项异常场景选择、操作等待时间控制及延时来单通知；不增加远程控制、网络故障注入、服务端结果查询或直接跳过材料校验的完成按钮。

### 4.8 重新开始、延时来单与系统通知

本节替代旧资料中“后台、锁屏不通知”“不发声音或振动”的约束；三类处理结果、材料要求及完成规则沿用前文。

#### 从重新开始到完成

| 步骤 | 操作与表现 |
| --- | --- |
| 1. 设置场景与时间 | 在隐藏的“工单调试”中使用默认三项或选择单项／多项，设置来单等待时间，例如 1 分钟或 2 分钟，点击“重新开始” |
| 2. 确认清除 | 确认框标题“重新开始”；正文“将清除当前全部工单、处理记录和未提交材料，并返回桌面。X 分钟后将收到 N 张新工单。”，下方列出本次所选场景；按钮“取消”“确认并返回桌面”。X 使用实际等待时间，N 使用实际所选场景数量 |
| 3. 准备并退出 | 必要通知与定时提醒条件具备后，清除旧进度、停用旧操作、保存新计划并交由系统安排；全部成功后自动关闭业务页面并返回桌面。计时从本次计划成功启用时开始，操作速度的正常／快速选项不改变该等待时间 |
| 4. 等待到达 | 此时业务列表为空。允许锁屏或划掉最近任务；无需 App 一直在前台，也无需联网。提前打开 App 仍显示空列表，等待原定时刻，不重新计时 |
| 5. 工单到达 | 到时按计划中保存的场景清单，一次性生成对应的待处理工单，每项一张；未选场景不生成。处理说明、照片、开始／完成／验收记录均为空，保留各自预置问题、位置和原始检查证据。成功保存后发出一条汇总通知，配合声音与振动 |
| 6. 查看并处理 | 点击通知进入“我的工单”的待处理分类，展示本次全部工单；选择任意工单，按既定流程开始处理、填写、上传并提交完成。支持 App 未运行时启动，也支持 App 已打开时进入 |

等待到达属于本地调试计划，不增加第四种工单业务状态。工单加入后的接收时间采用本次实际到达时间，原检查时间与证据保持原含义。

#### 通知呈现与点击

- 通知使用 Android 系统通知栏，标题为“新工单待处理”，正文为“您有 N 张新工单待处理，点击查看”。N 与本批实际新增工单数一致：默认 3，单项 1，多项按实际勾选数量，全选为 12；任一模式都只发一条通知。应用名称使用实际 App 名称，不出现“模拟”“演示”等说明。
- 使用“新工单提醒”通知类别，启用适合及时提醒的重要程度、系统通知声音和振动；每批只提醒一次，不按工单张数连续响铃，不循环播放或重复催办。支持系统允许时的横幅和锁屏展示，不强制打开 App 或覆盖锁屏。
- 到达时即使 App 在前台，也只产生这一条通知和一次声振提醒，列表同步更新；不额外叠加第二次声振或阻断弹窗，不打断当前输入。
- 点击通知后移除该通知；手动划掉通知不删除工单，也不再次补发。同一批工单仍可从 App 图标进入查看。通知不是自动开始处理或提交的入口。
- 从图标进入后处理了工单，再点击尚未移除的通知时，按当前实际状态展示；不把已完成工单重置成待处理。不再有待处理工单时显示正常空态，全部处理完成后移除本批通知。

#### 退出、持久化及重复开始

- “退出”指关闭 App 业务页面并返回桌面，不使用系统“强行停止”。返回桌面、系统回收进程和划掉最近任务后，都须在约定的验收设备上验证提醒可用，不能依赖界面倒计时或返回前台才触发。
- 同时只保留一个未到达计划。再次确认“重新开始”时，旧计划及旧通知失效，改按本次选定场景和新时间开始；连点不得创建多个计划。同批工单只加入一次、只发起一次提醒。
- “清除本地数据”会取消等待并立即恢复默认三项工单，不再于旧时间发通知；“恢复默认设置”只恢复操作速度，“恢复默认三项”只恢复待确认的场景配置，均不改变已安排的场景与来单时间。单张工单重置不产生新通知。
- 本机准备、保存或系统定时安排失败时，留在调试页并提示“未能重新开始，请重试”，保留原有可恢复数据及原计划，不进入已清空却无来单计划的状态。取消确认同样不清除数据、不退出。
- 本期验收以设备持续开机为前提；系统设置中的强行停止、重启手机后的自动恢复不作为本期必须能力。若已到时间但通知受系统限制，之后打开 App 时校准并补齐本批工单，防止永久空列表；这不算退出后通知验收通过，也不重复建单或补响。

#### 手机设置与验收条件

- MC62 已确认是 Android 13，需要按系统要求获取通知许可；普通 Android 手机按其系统版本处理。开始前检查通知许可、应用通知及“新工单提醒”类别是否开启；未满足时显示“请开启新工单通知”并提供“去设置”，暂不清除数据或退出。
- 需要系统授予定时提醒权限或配置后台运行条件时，在重新开始前完成相应引导与检查；拒绝后保留现有数据。通知许可与定时安排能力分别判断，不能只因通知许可开启便认定延时触发可靠。
- 声音、振动、横幅及锁屏内容遵从系统设置。完整声振验收须开启相应通知设置和可听音量，关闭静音／勿扰；App 不擅自提高系统音量或绕过勿扰。隐藏调试页可提供“通知设置”入口和相应说明。
- 对 MC62 和至少一台普通 Android 手机，分别实测桌面等待、锁屏等待、划掉最近任务、断网、点击通知启动及完整处理。记录计划时间、实际提醒时间、声音、振动和进入页面；不能只用前台计时、界面截图或系统通知调用成功代替实机提醒证据。
